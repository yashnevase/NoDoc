# Privacy Model

| Claim | Status | How it's enforced |
|---|---|---|
| File processing | Local only | All processing happens in the `backend/` Python sidecar, spawned as a child process by the desktop shell. No file bytes, filenames, or metadata are sent over any network interface. |
| Cloud upload | Disabled | No HTTP client in `engines/` or `backend/` is permitted to reach non-loopback hosts. Enforced by code review + a CI lint that greps for outbound network calls in these directories, and by the OS-level fact that the sidecar has no requirement for a route to the internet. |
| Required internet | No | The application launches, opens files, and processes them with the network adapter disabled. This is a Milestone 1 acceptance test, run before every release. |
| Telemetry | Disabled by default | No telemetry code ships in Milestone 0-6. If ever added, it will be opt-in, off by default, and documented here before release — not added silently. |
| Account | Not required | No login screen exists in the product. There is no server to log into. |

## What "local" means concretely

- The React frontend talks only to `127.0.0.1:<random-port>`, a port opened by the Python sidecar at launch and never exposed beyond loopback.
- A random per-session token (generated by the Rust/Tauri host) gates every request to that port, so no other local process can query it either.
- Temporary working files are written under the OS temp directory in a per-job subfolder and deleted after the job completes (see `backend/app/services/tempfiles.py` once implemented).
- The user's original file is never modified in place; output goes to a new file (see File Safety rule in the architecture doc).

## Auditing this claim yourself

Anyone can verify these claims by: (1) reading `engines/` and `backend/` — no code there references any non-loopback host; (2) running the app with the network adapter disabled and confirming full functionality; (3) inspecting outbound connections with a tool like Wireshark or Little Snitch during use.
